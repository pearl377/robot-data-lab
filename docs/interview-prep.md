# Robot Data Lab 面试准备手册

适用岗位：具身智能数据／算法工程。回答依据为本仓库的 CPU 实现和已保存的实验结果，GPU 部分明确标记为待运行。

## 1. 一分钟项目介绍

> 我做的是一个面向机器人模仿学习的数据工程与实验项目。主要目标是把公开机器人演示数据变成可检查、可追溯、可以重复训练和评估的数据流程。
>
> 数据使用 LeRobot v3 格式的公开真实机器人演示，共 50 条轨迹、11,939 帧，包含两个相机、关节状态和动作。我实现了文件完整性校验、轨迹结构和数值检查、视频时间戳定位、任务标注管理，以及阶段缓存和报告生成。
>
> 为了验证数据到模型的整条流程，我用双相机 RGB 网格和关节状态训练了一个 CPU MLP 行为克隆基线。按完整轨迹划分 40 条训练、10 条验证，跑了 3 个训练种子，离线 MAE 为 2.5325，相比复制当前状态的对照低约 14%。
>
> 这个结果验证的是离线数据与训练流程，还没有机器人闭环成功率。SmolVLA 和 LIBERO 目前只完成了固定版本的运行入口，后续需要 Linux/CUDA 环境验证。

不必逐字背诵。练习顺序是：目标 → 数据 → 实现 → 实验 → 结论和范围。

## 3. 高频问题与回答要点

### Q1：这个项目解决了什么问题？

回答：机器人训练数据同时包含连续时间信号、图像、动作和任务描述，文件能读出来并不代表可以直接训练。这个项目把版本和完整性检查、轨迹质检、样本构建、训练与评估串起来，让异常可以定位，实验可以追溯。

追问时可以展开：坏数据明确报错；可疑轨迹保留原因；重复运行可以复用已校验的计算阶段；所有结果都能回到固定数据版本和配置。

### Q2：数据是你自己采集的吗？

回答：不是。我使用公开真实机器人演示数据，完成的是采集后的数据处理和实验工程；没有操作机器人采集数据的实战结果。

如果讨论未来采集方案，可以提出机器人与相机标定、时间戳记录、状态/动作定义、任务标签、采集者与场景元数据、成功/失败覆盖和质量验收，但要明确这是设计方案。

### Q3：你做的部分和 LeRobot 的部分怎样区分？

回答：上游提供数据、格式和 VLA 的官方训练入口。本仓库实现了读取这个固定数据版本的管线、质检与筛选规则、标注 sidecar、轻量 MLP 基线、离线实验协议、缓存与报告。GPU 命令封装调用上游工具，没有实现新的 VLA 网络。

本地 CPU 流程没有安装或调用完整 LeRobot 训练栈；它通过 Pandas/PyArrow/PyAV 读取符合 LeRobot 格式的数据。面试时可直接用文件和函数证明具体实现，避免笼统地说“复现了整个 LeRobot”。

### Q4：一条训练样本长什么样？

回答：模型输入为同一时刻的 6 维关节状态，以及两个相机各自缩小到 8×8 的 RGB 图像并展平后的数值，合计 390 维；目标为该帧记录的 6 维动作。episode ID 和 frame ID 用来追溯样本和划分数据，不输入网络。

RGB 网格是直接缩放的图像特征，没有使用预训练视觉编码器，也没有输入语言。

### Q5：为什么不能按帧随机划分训练集和验证集？

回答：同一轨迹的相邻帧高度相似，按帧随机拆分会让同一段演示同时进入训练和验证，容易高估泛化能力。我先固定完整轨迹的划分，再在每组轨迹内部使用采样帧。

限制：轨迹不重叠仍不等于场景、物体或采集会话不重叠。当前只验证固定划分上的留出轨迹表现；更强的泛化实验需要按场景或采集会话分组，并在调参后使用独立测试集。

### Q6：质量检查具体检查什么？为什么区分错误和警告？

回答：错误包括 NaN/Inf、状态和动作维度异常、重复或不连续帧编号、非单调时间戳、元数据不一致、缺失任务标签，以及视频抽样解码失败。这些问题会让轨迹失去结构有效性。

警告包括轨迹过短、状态跳变、长时间静止、时间间隔异常和低纹理/模糊。当前选择规则排除 `short_episode`、`state_jump`、`long_idle`；其它警告仍保留。这是可配置的规则筛选，没有训练一个质量评分模型，也没有证明规则等同于任务成功与否。

### Q7：这些筛选阈值怎么来的？会不会误删好数据？

回答：当前阈值是配置里的工程启发式，不是从大量人工标签学出的最优值。状态跳变以相邻帧各维状态差的最大绝对值计算；静止比例统计这个值小于 0.05 的时间步比例。当前最大跳变阈值为 35，静止比例阈值为 0.65，短轨迹阈值为 60 帧。

这些数值使用数据原生单位，不应跨机器人照搬。抓取、等待和接触过程中的停顿可能有效，后续应结合人工复核、阶段标签与规则误删率调整阈值，且不能用最终测试集挑阈值。

### Q8：过滤后效果提高了吗？

回答：本次没有证据证明提高。50 条轨迹全部通过当前规则，训练集过滤前后相同，所以程序跳过相同的 filtered 和 random-matched 训练，实际只跑了 raw 组的 3 个训练种子。

如果确实筛掉了轨迹，实验设计会比较 raw、filtered 和同轨迹数量的随机子集，保持验证轨迹、更新次数和 batch size 一致。轨迹数量相同仍不代表帧数相同，还需要检查样本量、任务分布和场景分布。

### Q9：视频与动作怎么对齐？

回答：v3 的一个视频分片可能包含多条轨迹。先根据 episode 元数据定位相机分片，再用 `from_timestamp + 当前帧 timestamp` 得到视频时间，利用 PyAV 解码匹配帧。请求按文件聚合后顺序解码，避免逐样本重复打开视频。

当前匹配是带容差的工程实现：匹配窗口使用 `max(0.1, 2 × tolerance)` 秒。它不能证明传感器物理同步，也不应称为严格逐帧同步。质检只抽查 500 次；构建特征时会检查实际选中的图像，缺帧则报错，不用全零图像继续训练。

实现参考：[`video_reference`、`sample_video`、`build_features`](../robot_data_lab/data.py)。v3 的分片与元数据设计见 [LeRobot 官方格式说明](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)。

### Q10：为什么用这么小的 MLP？是不是太简单？

回答：它是低成本验证数据管线和实验协议的基线，在 CPU 上可以完整复跑。输入是 390 维，两个隐藏层各 128 维，输出 6 维。模型简单，便于检查标签、归一化和对照实验是否合理。

限制：8×8 网格丢失很多细节，单帧输入没有显式时序建模，模型也不理解语言。它不代表 VLA 的能力上限。复杂模型升级前应先做 state-only、图像置乱或遮挡等消融，验证图像是否真正提供了信息；这些消融尚未运行。

### Q11：归一化怎样避免信息泄漏？为什么训练用 MSE、评估用 MAE？

回答：每个训练组只使用自己的训练样本计算输入和动作的均值与标准差，小标准差截断到 1e-3。验证样本使用训练统计量变换，不参与拟合。损失是标准化动作的 MSE，预测再还原到原生单位计算 MAE。

MSE 对大残差惩罚更重，是当前回归基线的选择，并不保证最优。MAE 更方便描述平均绝对误差；归一化 MAE 用来补充不同维度尺度的影响。对照实验共享由 raw 训练集动作计算的指标尺度，避免每组用不同尺度比较。

### Q12：为什么要加“复制当前状态”这个对照？

回答：当前数据的状态与动作都是同名的 6 个关节/夹爪位置字段，直接输出当前状态是一个简单但有意义的对照。机器人连续运动中，目标动作可能与当前状态接近，所以仅优于训练集均值动作并不充分。

当前 MLP 的平均 MAE 为 2.5325，复制状态对照为 2.9439。相对下降的计算是 `(2.9439 − 2.5325) / 2.9439 ≈ 13.97%`。这表示该固定验证划分上的离线误差下降，不是抓取成功率提升 14%，也不能单独证明视觉特征有效。

### Q13：MAE 的单位是什么？±0.0454 是置信区间吗？

回答：这里用数据原生单位，没有将它统一换算成角度、弧度或毫米。整体 MAE 是验证样本和动作维度上的平均绝对误差，还会输出逐关节误差，避免总体平均掩盖某些维度的问题。

±0.0454 是 3 个训练种子的样本标准差，分母为 `n−1`，不是 95% 置信区间，也不是换数据划分后的方差。若要量化数据抽样不确定性，应以轨迹为单位进行 bootstrap 或多次分组划分，不能把高度相关的帧当作独立样本。

### Q14：帧平均与轨迹宏平均 MAE 有什么区别？

回答：帧平均会让更长的轨迹占更大权重；轨迹宏平均先计算每条轨迹的平均误差，再对轨迹等权平均。两者一起看，能够判断总体结果是否主要被长轨迹影响。当前实验 JSON 同时保存了这两个指标。

### Q15：离线误差低，为什么不代表机器人一定能完成任务？

回答：离线评估只在已有演示的观测上预测动作。闭环执行时，模型的动作会改变下一时刻的状态，一次偏差可能让机器人进入训练数据未覆盖的状态，后续误差继续积累。

后续需要仿真或真机的闭环成功率、超时率和失败类型分析。DAgger 提供了一种通过策略访问状态上的专家标注改进训练分布的思路，但本项目未实现该算法，也没有相应实验结果。该问题与方法可阅读 [DAgger 原论文](https://arxiv.org/abs/1011.0686)。

### Q16：缓存和“断点恢复”到底恢复到哪一层？

回答：恢复的是流水线阶段。缓存键由配置、Python 模块代码、数据 manifest 和记录的环境共同计算；只有阶段完成且输出文件 hash 一致时才复用。阶段执行前写 running，完成后写 complete；失败保存异常信息。缓存不适用或使用 `--force` 时重新执行计算。

CPU 训练没有实现优化器步级续训。checkpoint 保存模型参数与归一化统计，不保存 AdamW 优化器状态和当前迭代位置，因此某次训练中断后会重新跑实验阶段。不能把阶段复用说成“训练中断后无损续训”。

### Q17：怎样保证下载的数据可靠？

回答：配置强制使用完整 commit SHA；下载先写 `.partial` 文件，完成后替换目标文件，并记录文件字节数和 SHA-256。重跑时校验已下载文件；离线执行也校验源 manifest 与文件 hash。

SHA-256 能检测相对于已记录内容的变化，但首次本地计算的 hash 不是独立的真实性认证。这里还依赖固定版本和 HTTPS 来源。当前下载失败会重试，没有实现 HTTP Range 字节级续传。

### Q18：标注是如何处理的？你使用 VLM 自动标注了吗？

回答：从原始轨迹元数据导出单独的 JSONL，包含 episode ID、任务文本、来源、复核状态和备注，不覆盖原始数据，也不覆盖已有人工编辑。检查重复、遗漏、空文本和状态是否合法。

当前没有运行 VLM 标注，也没有人工完成语义复核。虽然 schema 允许 `vlm_suggestion` 来源，但这只是一种来源类型。标注更正尚未回写训练数据，本地 MLP 也没有语言输入，不能说“模型使用了清洗后的语言标签”。

### Q19：14 项测试覆盖了什么？

回答：覆盖正常轨迹、NaN 动作、逆序时间戳、状态跳变、动作维度、重复帧、标注来源与覆盖、GPU 命令约束、轨迹划分、训练集归一化、路径越界、禁止输出 NaN JSON、训练确定性与 checkpoint，以及合成视频的时间戳匹配。

测试通过不意味着真机安全、语义标签完全正确或 GPU 集成已验证。完整 CPU 数据流程另有实跑记录，测试和实跑分别提供证据。

### Q20：数据扩大到百万轨迹时怎么做？

回答：当前 `load_dataset` 使用 Pandas 将 Parquet 拼接到内存，特征也写成单个 NPZ，适合当前小规模样例，没有证明工业规模处理能力。

扩展计划是按分片扫描和按轨迹流式处理、分区保存特征与质检结果、按分片记录校验和及完成状态、限制视频解码并发，并记录吞吐、内存峰值与失败重试指标。官方的流式数据读取可以作为后续选项；这些是设计建议，尚未实现或压测。

### Q21：这个项目和 VLA 有什么关系？

回答：本地模型是视觉特征与状态到动作的行为克隆，没有语言条件，不属于 VLA。项目与 VLA 的联系在于多模态机器人数据的组织、质量管理和可复现实验入口。

SmolVLA 部分固定了上游代码、数据和 VLM 版本，封装 Linux/CUDA 的训练与 LIBERO 评测命令；目前没有运行结果。不能说完成了 VLA 微调、提出了新算法或复现了论文成功率。方法介绍可从 [SmolVLA 官方文档](https://huggingface.co/docs/lerobot/smolvla) 阅读，并与本仓库的实际运行状态分开。

### Q22：项目最值得改进的地方是什么？

回答：优先补足能够支持结论的实验。先加入 state-only 和图像置乱消融，判断模型是否使用视觉信息；再按轨迹分析误差、补充独立测试划分与有人工复核的质量样本；之后在 GPU 环境中完成 SmolVLA 小步训练和 LIBERO 闭环验证。对大数据量的支持另通过分片流式处理及性能测量推进。

这些属于下一步计划，当前简历不把它们计为完成项。

### Q23：用过 AI 编程工具吗？你实际掌握什么？

按真实情况回答：项目开发使用了 AI 编程辅助。讲清自己实际完成或验证过的需求设定、代码理解、运行操作和结果分析；还没掌握的部分不要描述为独立设计。准备好解释关键函数，并现场做一个小修改或定位一个失败测试，用具体表现说明能力。

## 5. 五分钟现场演示

先进入已经安装环境并下载数据的仓库根目录。下面命令用于 Windows PowerShell，不会启动 GPU 训练。

```powershell
# 1. 展示实际环境。当前应为 Windows / CPU。
& .\.venv\Scripts\python.exe -m robot_data_lab doctor

# 2. 离线验证数据并复用已完成阶段；不会重新下载数据。
& .\.venv\Scripts\python.exe -m robot_data_lab run-local --offline

# 3. 演示标注格式检查，解释 reviewed_rows = 0 的含义。
& .\.venv\Scripts\python.exe -m robot_data_lab annotations validate

# 4. 将测试临时文件限制在仓库的忽略目录，然后运行测试。
```
